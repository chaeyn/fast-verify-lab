# App Server 경로의 초기 지연 시간 비교

2026-10-01에 같은 모델 설정으로 기존 exec 경로와 새로운 App Server 경로를 비교했다. 초안은 gpt-6-luna / low / priority, 검토는 gpt-6.1-sol / high / default를 요청했다. 검토의 추론 수준을 낮추지 않았다.

세 사례를 두 경로로 각각 실행했다. 두 계산 질문과 8문장 설명 질문이며, 두 번째 사례에서는 경로 순서를 바꿨다. 동시에 모델을 호출하지 않았다. App Server 프로세스는 세 사례 동안 유지했고 각 호출은 새 ephemeral thread에서 실행했다. 기존 exec는 매 호출 새 프로세스·세션을 사용했다.

| 항목 | exec | App Server |
|---|---:|---:|
| 첫 표시 중앙값 | 5.36초 | 2.99초 |
| 검토 완료 중앙값 | 14.00초 | 12.96초 |
| 전체 입력 토큰 | 103,546 | 61,857 |
| 실행 수 | 3 | 3 |
| 호출 실패 | 0 | 0 |

첫 표시는 exec의 완성된 초안, App Server의 첫 응답 조각을 뜻한다. 사용자가 내용을 보기 시작하는 시점을 비교한 값이며 생성 완료 시간과는 다르다. 완성된 초안 시간은 원본 기록의 first_answer_ms에서 확인한다.

설명 질문에서는 첫 표시가 7.47초에서 2.99초로, 검토 완료는 23.38초에서 18.00초로 줄었다. 첫 계산 질문에서는 첫 표시 5.36초와 5.14초로 차이가 작았다. 따뜻한 서버에서 반복한 계산 질문에서는 첫 표시 4.78초와 2.56초를 기록했다.

변경에는 프로세스 재사용, 첫 답변 스트리밍, 임시 설정 환경, 질문 답변용 지침이 함께 포함됐다. 각 변경의 효과를 따로 분리하지 않았다. 사례 수가 적고 캐시·네트워크 상태도 영향을 주므로 일반적인 속도 향상률을 보장하는 결과로 해석하면 안 된다. 세 검토 모델은 모두 초안을 accepted로 판정했으며, 이 판정 자체가 독립적인 정확도 증명은 아니다.

`speed-comparison.json`에 이벤트·호출별 사용량·단계별 시간을 보존했다. 첫 응답이 빠르더라도 high 검토가 끝날 때까지 추가 시간이 필요하다.
